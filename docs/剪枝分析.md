在本项目中，**Expectimax + NNUE** 引擎（位于 `src/core/expectimax/` 与 `src/inference/nnue/`）针对暗棋（非完全信息 / 随机博弈）的特性，构建了一套多层次、软硬协同的剪枝与搜索加速体系。

下面结合代码实现与博弈理论，对这套剪枝策略进行全面解析：

---

### 一、 核心剪枝机制全景

暗棋博弈树由两种节点组成：
1. **决策节点（Decision Node）**：玩家主动选择动作（走子、吃子）；
2. **机会节点（Chance Node）**：由概率主导的非确定性动作（翻暗棋、炮吃暗子）。

引擎构建了以 **Star1 期望值剪枝** 为核心、辅以决策节点高级启发式剪枝的综合树搜索架构：

```
                    [ 根节点: Iterative Deepening ]
                                  │
                  ┌───────────────┴───────────────┐
                  ▼                               ▼
       [ 决策节点: Negamax ]             [ 机会节点: Star1 (flip_value) ]
          ├─ 重复局面剪枝 (Repetition)       ├─ 理论界限截断 (ai >= u / bi <= l)
          ├─ 置换表截断 (TT Cutoff)          ├─ 动态窗口收缩 (cl, cu)
          ├─ 启发式走法排序 (Ordering)       └─ 子分支提前截断 (v <= ai / v >= bi)
          ├─ 晚走子减深 (LMR)
          └─ Alpha-Beta 截断 (alpha >= beta)
                  │
                  ▼ (depth <= 0)
        [ 静态搜索: Quiescence Search ]
          ├─ 静态评估截断 (Stand-pat Cutoff)
          └─ 吃明子 MVV-LVA 截断
```

---

### 二、 机会节点剪枝：Star1 期望值算法（核心特色）

在 `src/core/expectimax/search.rs` 的 `flip_value` 函数中，实现了 Bruce Ballard 于 1983 年提出的 **Star1 算法**。

#### 1. 数学原理
常规 Alpha-Beta 无法直接处理机会节点，因为期望值是多个分支的加权平均，单看某一分支无法断定整体期望。
但暗棋评估值有全局理论界限 $[l, u] = [-1.0, 1.0]$（对应 `VMIN`, `VMAX`）。若已知：
- $v_{sum}$：已搜索机会分支的概率加权和；
- $rem = 1 - \sum p_i$：剩余未搜索分支的总概率；
- $p$：当前待评估分支的概率。

则当前分支的理论上下界可推导出子节点必须达到的阈值：
- **Fail-Low 阈值**：$a_i = \frac{\alpha - v_{sum} - rem \times u}{p}$
  - 含义：即使剩余所有未搜分支全部取得理论最大值 $u$，只要当前分支 $\le a_i$，总期望也绝不可能达到 $\alpha$。
- **Fail-High 阈值**：$b_i = \frac{\beta - v_{sum} - rem \times l}{p}$
  - 含义：即使剩余所有未搜分支全部取得理论最小值 $l$，只要当前分支 $\ge b_i$，总期望也必定超过 $\beta$。

#### 2. 代码实现机制
```rust
// 当阈值超出理论极值时，直接提前跳出整个机会循环（无需探索后续分支）
if ai >= u { return Ok(alpha); } // Fail-low 截断
if bi <= l { return Ok(beta); } // Fail-high 截断

// 将子节点的 Alpha-Beta 窗口动态紧缩为 [cl, cu]
let cl = if ai > l { ai } else { l };
let cu = if bi < u { bi } else { u };

// 递归搜索子节点（使用紧缩后的窗口）
let v = -negamax(&next_env, &next_acc, depth - 1, -cu, -cl, cfg, ctx)?;

// 子节点返回后，再次检查是否触发提前终止
if v <= ai { return Ok(alpha); }
if v >= bi { return Ok(beta); }
vsum += p * v;
```
**优势**：由于紧缩了 $[c_l, c_u]$ 窗口，传给子节点的 Alpha-Beta 能大幅加速深层剪枝；一旦某个大概率分支结果较差或极好，后续低概率分支直接被完全剪除。

### 三、 决策节点剪枝策略

#### 1. 置换表（Transposition Table, TT）剪枝
- **状态哈希**：采用 64 位 Zobrist Hash（`zobrist::zkey`），编码了棋盘 32 格状态、双方暗袋计数以及走子方。
- **探测剪枝**：在 `negamax` 入口处检查置换表。当 `e.depth >= depth` 时：
  - `flag == 1 (exact)`：真值，直接返回 `e.value`；
  - `flag == 2 (fail-high / 下界)`：若 `e.value >= beta`，产生截断；
  - `flag == 3 (fail-low / 上界)`：若 `e.value <= alpha`，产生截断。
- **走法启发转移**：即使 `depth` 不够无法直接截断，TT 中记录的 `e.best`（最佳历史走法）会被提升至首位（PV-Move），极大提高后续分支的剪枝概率。

#### 2. 晚走子减深（Late Move Reductions, LMR）
在 `negamax` 遍历排序后的走法时：
```rust
let quiet = !m.is_chance && !m.is_capture;
let v = if cfg.feat(FEAT_LMR) && quiet && i >= 3 && depth >= 3 {
    // 1. 先用深度 (depth - 2) 和零窗口 [-alpha - 1e-6, -alpha] 探测
    let probe = -negamax(&child, &child_acc, depth - 2, -alpha - 1e-6, -alpha, cfg, ctx)?;
    if probe > alpha {
        // 2. 探测失败（产生了意外的好成绩），触发 Re-search 全深度重搜
        -negamax(&child, &child_acc, depth - 1, -beta, -alpha, cfg, ctx)?
    } else {
        probe
    }
} else {
    move_value(...)
};
```
- **核心逻辑**：排在第 3 个以后的静走子（非吃子、非机会动作）通常不具备战术破坏力，大概率不会超越当前已知的最佳得分。先以减深（`depth - 2`）和零窗口探测，大部分分支会直接在浅层 Fail-Low 退出，仅极少数需要重搜。

#### 3. 静态搜索与吃子剪枝（Quiescence Stand-pat Cutoff）
- **解决水平线效应**：深度耗尽后，不直接返回估值，而是调用 `quiesce` 继续延展吃明子走法。
- **Stand-pat 剪枝**：
  进入静态搜索后先评估当前局面 `stand = eval_acc(...)`：
  - 若 `stand >= beta`，说明玩家即使什么都不吃，当前局面也足以引发 Beta 截断，直接返回 `stand`；
  - 仅生成并遍历吃明子走法，并严格按 **MVV-LVA** 排序。一旦吃子后得分突破 Beta，立即 `break` 截断。

#### 4. 路径重复局面剪枝（Repetition Cutoff）
- 维护从根节点到当前节点的祖先哈希栈 `ctx.path`。
- 静走子循环（如双方互相兜圈）会导致哈希碰撞，一旦命中祖先记录，直接剪除分支并判定为和棋（返回 `terminal_value`），避免了搜索树在循环分支中无限发散。

### 四、 走法排序（Move Ordering）：剪枝效能的基石

剪枝的本质是**先看最好的分支**。若最优走法排在第一位，Alpha-Beta 搜索复杂度将从 $O(b^d)$ 降至理论最优的 $O(b^{d/2})$。

在 `src/core/expectimax/ordering.rs` 中，走法按优先级从高到低排列：
1. **TT Best Move**：置换表命中走法（置顶在索引 0）；
2. **吃明子走法（MVV-LVA）**：得分区间 $[1{,}000{,}000 + \text{victim} \times 8 - \text{attacker}]$，优先使用低子力换取高子力；
3. **杀手走法（Killer Moves）**：得分 $900{,}000$ / $800{,}000$，记录当前同一剩余深度曾引发 Beta 截断的两个静走子；
4. **历史启发（History Heuristic）**：累计统计全局导致剪枝的静走子起点到终点频次，按 $depth^2$ 加权；
5. **炮吃暗子（Chance 动作）**：得分 $-900{,}000$；
6. **翻棋（Flip Chance）**：得分 $-1{,}000{,}000$（垫底，因为翻棋展开暗袋分支的分支因子极大，且通常信息量最不稳定，应最后考虑）。

### 五、 NNUE 与 Expectimax 剪枝的深度协同

NNUE 的引入不仅提升了局面评估的棋力，更在底层直接决定了剪枝的效率：

| 机制 | 传统手工评估 | NNUE 增量评估（本项目实现） | 对剪枝的影响 |
| :--- | :--- | :--- | :--- |
| **单节点耗时** | 极快（几纳秒）但精度低 | **双累加器（DualAccumulator）增量更新**，仅需累加特征差分，微秒级叶评估 | 保持极高 NPS（节点每秒），确保在节点预算内达到深度剪枝 |
| **值域连续性** | 阶梯式离散分值（吃一子跳几百分） | 连续非线性数值 $[-1.0, 1.0]$，具备微小位置势能敏锐度 | 极大减少 Alpha-Beta 窗口震荡，加速窗口收敛 |
| **Star1 判定速度** | 误差大，容易高估/低估剩余概率分支 | 对翻出各种暗子后的局面区分度极高 | 期望值累加后**更早突破 $a_i$ 或 $b_i$ 阈值**，大量跳过低概率暗袋分支 |
| **LMR 误剪率** | 静态分不准导致 Re-search 频繁 | 排序准确度提升，好走法更聚焦在前 1~2 个分支 | LMR 试探探测失败率显著下降，极少触发全深度重搜 |

---

### 六、 总结与工程考量

本项目的 Expectimax + NNUE 剪枝体系：
1. **理论完备**：以 **Star1 期望值界限理论** 严密处理暗棋特有的暗袋翻子随机性；
2. **分层递进**：**TT/Killer/History 排序优化** $\rightarrow$ **Star1/Alpha-Beta 强截断** $\rightarrow$ **LMR 弱走法降权** $\rightarrow$ **Quiescence 吃子消除水平线效应**；
3. **软硬协同**：NNUE 的双视角累加器在维护 $O(1)$ 增量计算特性的同时，提供高置信度的叶评估，为 Star1 和 Alpha-Beta 的快速收敛提供了数学保证。
